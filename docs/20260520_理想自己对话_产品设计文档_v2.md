## Problem Statement

目标用户（25-35 岁都市人群，男性 + 女性）面临的核心问题：
- 工作压力大、自我攻击、拖延等情绪和行动卡点
- 想要"看见自己有没有变化"，但缺少一个能让自己"看见模式"的工具
- 想要"在此刻被推动启动行动"，但现有解决方案（找朋友聊天、刷社交媒体、代偿行为）都是被动的、临时的
- **男性特有痛点**：不能跟兄弟说脆弱的话，跟女朋友说又怕给对方压力，更难找到倾诉对象
- **女性特有痛点**：情绪敏感、自我攻击更频繁，但也更愿意寻求帮助

**用户原话**："当我遇到问题的时候，我想看一下自己有没有什么变化。或者有时候隔了一段时间想起来，想看看自己有没有什么变化，或者是启发。"

**核心需求**：
1. **洞察层**："我这是咋了？"（理解自己的模式）
2. **推动层**："在此刻被推动一下"（启动行动）

## Demand Evidence

**当前真实用户**：
- 创业者自己和她对象
- 创业者的反馈："最近打开次数少了，因为没办法看见自己的觉察或洞察，没有痕迹。我只能把它当成我好像跟一个人聊了天，哦，这个聊天还挺有用的。"

**潜在用户**：
- 创业者的朋友们有类似问题（工作压力、自我攻击）
- 第二篇笔记（"男生不会跟女朋友说的话"）显示男性用户有共鸣（30% 点击率，高于第一篇的 18.2%）
- 她们/他们现在的解决方案：找朋友聊天 + 刷社交媒体看相关内容 + 代偿行为（吃东西、刷短视频）
- 她们/他们不知道这个产品存在，尚未验证付费意愿

**关键洞察**：
创业者自己作为第一个真实用户，发现纯对话框没有留存价值。这个诚实的反馈揭示了产品的核心问题：**对话只是输入方式，模式识别和留痕才是产品的核心价值。**

## Status Quo

目标用户现在的解决方案：
1. **找朋友聊天**（最核心的）—— 但朋友不可能 24 小时在线，也不会记得"她上个月也说过同样的话"
2. **刷社交媒体看相关内容**（寻求共鸣/启发）—— 但内容是泛化的，不是针对自己的
3. **代偿行为**（吃东西、刷短视频）—— 逃避问题，没有解决问题

**成本**：
- 时间成本：每次遇到问题都要重新寻找解决方案
- 情感成本：反复陷入同样的模式，但看不见自己在重复
- 机会成本：没有一个工具能帮助她们"看见变化"和"被推动启动"

## Target User & Narrowest Wedge

**目标用户**：
- 25-35 岁都市人群（一二三线城市）
- 男性 + 女性
- 有拖延、自我攻击、情绪卡点、存在性孤独等问题
- 关注自我成长，愿意为"看见自己的模式"付费

**为什么不限性别**：
- 第二篇笔记（"男生不会跟女朋友说的话"）数据显示男性需求存在（30% 点击率）
- 男性更难找到倾诉对象（不能跟兄弟说脆弱的话，跟女朋友说又怕给对方压力）
- 产品本身不限性别（"理想的自己"对男性女性都适用）
- 动物形象对男性女性都有吸引力

**为什么不限一线城市**：
- 二三线城市也有同样的痛点（工作压力、自我攻击、拖延）
- 如果定价合理（99-199 元/月），二三线城市也付得起

**最窄的楔子**：
创业者自己（女性）+ 创业者对象（男性）。如果这个产品能让他们两个人每周打开 3 次以上，说明核心价值成立。如果他们自己都不愿意持续使用，说明产品方向有问题。

**验证指标**：
- MVP 上线后，创业者自己的打开频率是否回升
- 如果加了留痕机制，创业者自己还是不愿意打开 → 说明这个产品解决的是偶发需求，不是高频需求

## Constraints

**技术资源**：
- 对象（211 计算机软件工程专业），愿意做
- 备选方案：阿里灵光 APP 手搓

**时间约束**：
- 希望 1-2 周完成 MVP

**成本约束**：
- 技术开发成本可控（对象做）
- 需要考虑 AI API 调用成本（对话 + 模式识别）

## Premises

### 前提 1：模式识别是可行的
AI 可以从对话中自动识别出用户的"拖延模式""自我攻击模式"等，并且这些识别是准确的、有意义的。

**风险**：
- 如果 AI 识别错了怎么办？
- 如果 AI 识别出的模式太多、太碎片化怎么办？
- 如果 AI 识别出的模式太少怎么办？

**创业者的立场**：
- 宁可识别少（做好一个模式），也不要识别多（太碎片化）
- 备选方案：用户手动调整模式（如果精准度不够）

**需要验证**：模式识别的技术方案和精准度。

---

### 前提 2：用户会设置"理想的自己"
用户在第一次使用时，会填写"理想的自己"的三个维度（理想状态 + 理想场景 + 行动方向）。

**风险**（来自第二意见）：
- 25-35 岁一线城市女性在工作压力、自我攻击的状态下，很可能写不出清晰的"理想的自己"
- 或者写出来的是社会期待（"独立女性""财务自由"）而不是真实渴望
- 如果"理想的自己"是空的或假的，整个模式地图的对比就失效了

**创业者的立场**：
- 需要引导流程（给模板选项 + 参考例子）
- MVP 先做简单版，复杂版留到优化阶段

**需要验证**：让 5 个目标用户在 5 分钟内填写"理想的自己"，看她们能不能写出具体的、有画面感的、能指导行动的内容。

---

### 前提 3：用户会为"看见模式"付费
用户愿意为"看见自己的模式 + 被推动启动"这个价值付费。

**核心差异化**：
1. **vs 自己反思**：很少有人能通过自己反思看见模式（需要很强的内心探索能力和反思复盘能力）
2. **vs 通用 AI**：有记忆、能识别模式，不是纯对话流
3. **vs Flomo**：
   - Flomo = 主动记录灵感/点子，偏创作者
   - 本产品 = 倾听陪伴 + 行动推动，偏成长陪伴

**需要验证**：MVP 上线后，是否有人愿意付费。

---

### 前提 4：技术实现是可行的
对象可以在 1-2 周内实现这个 MVP（对话 + 模式识别 + 三个页面）。

**技术难点**：
- 模式识别用什么技术方案？（prompt 工程 vs 微调）
- 数据存储用什么方案？
- 1-2 周能做到什么程度？

**需要验证**：与对象讨论技术实现方案。

## Cross-Model Perspective

独立 AI 审视（Claude 子代理）提出了以下观点：

### 最强版本
一个能让你**看见自己重复模式**的对话镜子。每次对话后自动沉淀一张"模式卡片"（拖延、自我攻击、逃避等），卡片上显示这个模式出现了几次、上次是什么时候、跟"理想的自己"的距离有多远。核心价值不是对话本身，而是**让无意识的重复变得可见**。

### 关键洞察
**"最近打开次数少了，因为没办法看见自己的觉察或洞察，没有痕迹"**

这句话揭示了产品的本质：不是对话工具，是**觉察留痕工具**。用户不需要更好的对话，她需要的是"我上周也是这样，我这个月第三次陷入这个坑了"这种被推着看见自己的感觉。对话只是输入方式，模式地图才是产品。

### 挑战的前提
**"理想的自己"这个设计有风险。**

问题：25-35 岁一线城市女性在工作压力、自我攻击的状态下，很可能写不出清晰的"理想的自己"，或者写出来的是社会期待而不是真实渴望。如果"理想的自己"是空的或假的，整个模式地图的对比就失效了。

建议：让 5 个目标用户在 5 分钟内填写"理想的自己"，验证这个设计是否可行。

### 48 小时原型建议
**先做模式识别 + 模式地图，跳过"理想的自己"。**

技术栈：Next.js + Vercel + Claude API（Haiku）+ Supabase

MVP 功能：
1. 对话框（输入）
2. 每次对话后，AI 自动生成一张"模式卡片"
3. 模式地图页：显示所有模式卡片，按出现次数排序
4. 点击卡片 → 看这个模式的历史记录（时间线）

跳过：理想的自己、模式详情页的复杂分析、任何美化设计

理由：先验证核心假设——"看见模式"是否真的能让用户持续使用。

### 创业者的回应
创业者选择**保留"理想的自己"**，但简化实现方式（三个维度 + 引导流程）。理由：
1. "理想的自己"是产品定位的核心，不能完全跳过
2. 可以通过引导流程降低用户填写门槛
3. 如果用户连简化版都填不出来，说明这个设计确实有问题，可以再调整

## Approaches Considered

### Approach A: 完整版（三个页面 + 理想的自己）
**Summary**: 对话页 + 模式地图页（含理想的自己）+ 理想的自己详情页 + 模式详情页

**Effort**: M（中等）

**Risk**: Med（中等）

**Pros**:
- 符合产品定位："理想自己对话"
- 给用户一个"北极星"，知道自己要往哪里去
- 模式地图有了对比基准（"我离理想的自己还有多远"）

**Cons**:
- 增加了 MVP 的复杂度
- 如果"理想的自己"是空的或假的，整个产品的价值主张就塌了
- 需要设计引导流程，增加开发时间

**Reuses**: 无（新产品）

---

### Approach B: 最小版（两个页面，跳过理想的自己）
**Summary**: 对话页 + 模式地图页 + 模式详情页（不包含"理想的自己"）

**Effort**: S（小）

**Risk**: Low（低）

**Pros**:
- MVP 更简单，更快验证核心假设
- 先验证"看见模式"是否真的有用
- 如果验证通过，再加"理想的自己"也不迟

**Cons**:
- 产品变成了"模式识别工具"，失去了"理想自己对话"的独特性
- 可能和 Flomo + AI 洞察的差异化不够明显
- 缺少"北极星"，用户不知道自己要往哪里去

**Reuses**: 无（新产品）

## Recommended Approach

**选择 Approach A（完整版），但简化"理想的自己"的实现方式。**

**理由**：
1. "理想的自己"是产品定位的核心，不能完全跳过
2. 可以通过引导流程（模板选项 + 参考例子）降低用户填写门槛
3. 如果用户连简化版都填不出来，说明这个设计确实有问题，可以在 MVP 验证后调整

### 产品形态

#### 导航栏结构（底部三个按钮）

1. **首页（日记本）** - 查看所有对话记录
2. **模式地图** - 查看所有识别出的模式
3. **理想的自己** - 查看和编辑个人设置

---

#### 页面 1：对话页（主页，默认页面）

**对话界面样式（日记本形式）**

**重要：不是左右气泡（像微信），而是上下排列（像日记）**

**布局方式**：
- 用户的话：左对齐，黑色或深灰色（#333333）
- 理想的自己的话：右对齐，浅灰色或粉色（#999999 或 #FFB6C1）
- 中间有留白，像呼吸的空间

**示例**：
```
今天有什么不想做的事吗？
                                        （理想的自己，右对齐，浅灰色）

我又拖延了，今天说好要写文章的
结果刷了一下午手机
（现在的我，左对齐，黑色）

我做到了。不是通过战胜拖延，
而是通过不再把它当作一个需要战胜的东西。
                                        （理想的自己，右对齐，浅灰色）

好的，我去做了
（现在的我，左对齐，黑色）
```

**对话流程**：
1. 用户打开对话页
2. 理想的自己说："今天有什么不想做的事吗？"
3. 用户输入
4. 理想的自己回复
5. 对话继续，直到用户表示结束
6. 对话结束时，AI 自动识别模式并输出

#### 页面 4：理想的自己页（个人中心）

用户点击导航栏的"理想的自己"按钮，进入个人中心页面。

**页面内容**：

三个维度：

### 引导流程（第一次使用）

**步骤 1：欢迎页**
- 简短介绍产品："这是一个能让你看见自己模式的对话工具"

**步骤 2：设置"理想的自己"**

**问题 1：选择你的核心特质**
- "如果用一个动物来代表五年后的你，你会选哪个？"
- 给选项（配图标/插画 + 特质描述）：
  - 🐯 老虎 - 果断、有力量、不拖延
  - 🐆 豹子 - 敏捷、专注、高效
  - 🐘 大象 - 稳重、智慧、有耐心
  - 🦊 狐狸 - 灵活、聪慧、善于应变
  - 🐺 狼 - 坚韧、独立、有目标感
  - 🦅 鹰 - 高瞻远瞩、自由、不被束缚
  - 🦌 鹿 - 温柔、敏感、与自然和谐
  - 🐻 熊 - 强大、保护、有安全感

**问题 2：你的理想场景**
- "五年后的你，在什么环境下做什么？"
- 给例子：在咖啡馆写作、在家陪孩子、在公司带团队...
- 用户自己填

**问题 3：你的行动方向**
- "为了朝这个方向靠近，你希望自己在哪些方面有行动？"
- 给参考选项（可多选）：
  - 不拖延，说做就做
  - 坚持创作/写作
  - 照顾好身体（运动、睡眠、饮食）
  - 建立边界，学会拒绝
  - 减少自我攻击，对自己温柔
  - 断舍离，简化生活
  - 深度工作，减少分心
  - 建立稳定的关系
  - 探索新的可能性
  - 其他（用户自己填）

**步骤 3：开始对话**
- 进入对话页，开始第一次对话

### 视觉方向

**情感属性**：温暖、有陪伴感、不冰冷

**整体风格**：温柔、治愈、低压

**色彩方案**：
- 背景：米白色到淡粉色的渐变（#FFF8F0 → #FFE8E8）
- 用户的文字：深灰色（#333333）
- 理想的自己的文字：浅灰色或粉色（#999999 或 #FFB6C1）

**字体**：
- 圆体或手写体
- 传达温暖、柔软的感觉

**界面布局**：
- 极简设计
- 留白充足（不要太拥挤）
- 像呼吸的空间

**参考方向**：
- 不要像：工具类 APP（todo 清单、日历）
- 要像：日记类 APP（Day One、格志）或者冥想类 APP（Calm、Headspace）

**"理想的自己"的视觉化**：
- 不是具体的人物形象
- 而是抽象的光
- 会呼吸（缓慢的放大缩小）
- 传达"温柔、接纳、陪伴"的感觉

**设计原则**：
- 不需要复杂，但要有感觉
- 信息层级清晰（用户能一眼看到重点）
- 交互状态完整（加载、空状态、错误状态）
- 边缘案例考虑（名字太长、模式太多、网络失败等）

### Q2: 模式识别的精准度
**问题**：如何避免识别错误、识别太多、识别太少？

**策略**：
- 宁可识别少（做好一个模式），也不要识别多（太碎片化）
- 备选方案：用户可以手动调整模式（删除、合并、重命名）

**需要验证**：MVP 上线后，观察创业者自己使用时的模式识别效果。
