## 0. 给接手者的使用说明

- **本文件是什么**：记录了项目从「发起人昨天晚上萌生的一个想法」，到经过一轮深度研讨、把想法打磨成可落地产品方向的全部过程与结论。
- **当前处于什么阶段**：**想法打磨阶段**。→ 还没有进入市场调研，也没有做竞品扫描，更没有开始写代码。发起人明确表示：**先把想法本身聊透，赚钱是后面的事**。
- **接手后的正确姿势**：
  1. 先完整读完本文件（尤其第 3、5、7、8 节），不要凭「一个找兴趣的 App 应该长什么样」的常识去臆测或自我发散——本项目的关键差异点恰恰在「反常识」的地基重构上（见第 3 节）。
  2. 第 5 节的「技术硬墙」是**红线**，任何方案设计都不得假设「可以被动读取用户手机数据」。
  3. 涉及「做哪一层 / MVP 切哪刀 / 模式是否合并」等**未定事项**，以第 7、8 节为权威清单，不要自行拍板替发起人决策；这些是已明确要求「共同商榷」的内容。
  4. 更新本文件时，遵循第 10 节「变更记录」，并把新结论写进对应章节，而不是只在对话里说。
- **本项目的一条贯穿原则**：**陪伴探索，不给答案，不施压**。目标用户是迷茫期甚至低谷期的人，产品调性、文案、机制设计都必须服从这条原则（详见 4.3 与 5.3）。

## 1. 项目发起背景与动机

### 1.1 发起人画像（必要背景，仅保留与项目决策相关部分）

- 性别/年龄：男，24 岁（即将 25 岁，2001-12-28 生，摩羯座）。
- 学历/专业：2024 年毕业，软件工程专业（东北林业大学）。
- 技术基础：具备 AI 模型本地化部署、Streamlit + RAG 等项目实战经验——**这意味着「自创业做 App」在开发能力上不是零起点**，但产品设计、市场验证、商业化仍是短板与空白。
- 当前个人处境（这是本项目的**原始痛点来源**）：处于**考研三战、国考、求职、AI 微创业多线并行**的探索 / 转型期，时间紧张、方向不确定、机会成本焦虑重。
- 结论：**发起人本人就是第一阶段目标用户群的原型（dogfooding 起点）**。既是优势（真实痛点、真实体感），也是风险（需警惕「只为自己设计」的偏差）。

### 1.2 触发点（发起人的原话要点）

- 「自己昨天萌生的一个想法」。
- 「除了四处碰壁探索之外，我的想法是也可以借助 AI、凭借自己的想法和能力去，加速解决所面临的困境，因为时间在任何时段都是弥足珍贵的。」
- 即：**做这个 App，首先是为了给自己造一把「更快走出迷茫期」的工具；其次才是把它变成生意。**

### 1.3 意图（三重，按优先级）

1. **解决自己当下的困境**：不再靠「四处碰壁」的盲目试错，用工具化、系统化的方式加速找到方向。
2. **用 AI + 自身能力加速破局**：核心驱动是「时间珍贵」，要的是效率型工具，而非又一份让人更焦虑的清单。
3. **长期：做成有价值的产品 → 自创业 → 获取利润**。发起人明确希望走通「从 0 到 1 售卖产品并获取利润」的**全套 SOP**，但承认这是后话，是长期目标。

### 1.4 目标用户（分阶段）

- **第一阶段（当前定位）**：与发起人一样、**20 多岁、职业与生活仍处于探索期**的人。
- **第二阶段（待基础版本迭代后市场验证可行，再启动）**：覆盖**更年长的转行人群**，通过版本迭代逐步扩展。
- 该分阶段策略由发起人在研讨中明确确认，是后续所有产品规划的前提。

## 2. 原始想法存档（来源《探索自我.docx》）

> 以下为发起人原始文档的核心内容，**忠实保留其原始设想与自我觉察**，作为「想法演化起点」的存证。
> **原文全文（逐字、未改写）请见本文档「附录 A」**；同时另存有独立文件 `探索自我（原文·逐字转录版）.md`。本节为便于阅读的结构化转写，附录 A 为不可删改的原始底稿，二者互为对照。

### 2.1 原始设想（一句话）

> 想做一个手机软件：**能帮人找到自己真正感兴趣的、或极大概率感兴趣的、或爱好的一个 App。**

### 2.2 原始文档四点（结构化转写，保留原意）

1. **痛点：20 多岁的探索期 / 迷茫期，说不清自己真正感兴趣什么。**
   - 别人问你「真正感兴趣的、爱好是什么」，球类这类可以说出来，但种种原因并没有每天去做、去坚持。
   - 真正精确的答案，思考过后「脑子里觉得有很多，或者想不出来」，不像小时候被问「长大后想做什么」时能脱口而出（当太空人、科学家）。
   - 发起人的关键推论：**「要做成一件事，肯定得先自己感兴趣，然后再去努力/付出行动/坚持，才有可能成功或取得好结果；勉强去做没兴趣的事，效果不会好、上限也不高。」**（⚠ 这一前提在研讨中被部分修正，见 3.1。）

2. **原始方法论：看手机里「花钱最多的地方」作为兴趣信号。**
   - 逻辑：在当前经济环境下，你愿意在这些地方花钱，证明它对你有吸引力，你也较可能感兴趣。
   - 发起人自己已察觉局限：**不是全、也不保证准确率**——有人自律、有人拿手机看书充实自己、有人正常社交、也有人抱着手机玩游戏看剧。
   - 初心：让人找到「虚拟世界奶头乐之外」的、那些**想提升、想成为更好自己**的人所能握住的一个「明亮的点」——「很清晰知道这是我感兴趣的，如果要做，我会很认真、很投入地去做」。

3. **关键设计问题：工作模式与工作期限。**
   - 多久能产出想要的结果（探寻出感兴趣的事）？
   - 时间范围：**只能从「安装后到现在」监测，还是可以获取用户「安装前」的历史数据？**
   - 隐私：敏感数据要给用户**选择权**，由用户自己判断是否让软件读取；**安全问题很重要**。（发起人当时已意识到隐私，但低估了技术层面的可行性问题。）

4. **延展设想：兴趣确定之后的「行动层」与「未来自我对话」整合。**
   - 确定兴趣、且准确可靠后，应给出**辅助性建议**：怎样去实现 / 利用 / 如何行动（围绕这个兴趣或爱好；名称暂不定）。
   - 发起人与女友之间有过一个理想化的设想：「**我的页面**」可以**与「设定的未来的自己」对话**，给出建议。
   - 设想：探索出兴趣后，将「探索」与「未来自我对话」这两个 App **对接 / 整合到一块**——先监控探索得出可靠结果，再由用户编辑导入或直接转入（取决于两个 App 的功能是否已整合），形成**一套更完整的闭环**。
   - 发起人原话：「先监控探索得出准确可靠的结果后，然后再由用户编辑导入或者直接转入……形成一套更加完整的闭环。」

### 2.3 原始想法中发起人已自我察觉的不足

- 「看花钱最多的地方」不保证准确率、不全面。
- 隐私与数据安全问题需要处理。
- 「多久出结果」「能不能读历史数据」——当时是开放问题，没有答案。

> 这些自我察觉，正是研讨中「地基重构」的出发点。

## 3. 核心地基重构：从「探测器」到「验证·养成引擎」

### 3.1 前提修正：兴趣是「养出来」的，不是「测出来」的

- **原始前提的问题**：原文档隐含「兴趣是一个可以被测量/探测出来的既有答案」。
- **研讨修正**：心理学更站得住的说法是——**兴趣更多是通过「投入 → 胜任感 → 小成就感」逐渐生长出来的，而不是靠一个工具一次性「探测」出来的。**
- **由此得出的核心定位转变**：
  - ❌ 不做 **「兴趣探测器」**（问半天，给你一张兴趣清单——用完就走、还不准、难变现）。
  - ✅ 要做 **「兴趣验证·养成引擎」**（给你小实验，边做边确认，边做边长出兴趣——留得住、付得起钱）。
- **一句话内核**：「发现」只是引子；**「边做边验证、把兴趣养成能力」才是这个产品真正在卖的东西**。它同时解决三件事：准确率、留存、付费。

### 3.2 两种模式的对比（重构前 vs 重构后）

| 维度 | ❌ 探测器模式（原设想） | ✅ 验证·养成引擎（重构方向） |
| --- | --- | --- |
| 核心问题 | 你喜欢什么？测出来 | 什么值得你投入？边做边确认 |
| 数据来源 | 被动读手机数据（系统层被堵死，见第 5 节） | 用户主动记录 + 兴趣小实验试玩 |
| 用户动作 | 几乎不用做，机器替你算 | 每天 1 分钟记录 + 每周 1 个小实验 |
| 输出 | 一张「兴趣清单」 | 一个投入方向 + 30 天实验路径 |
| 心理感受 | 像被贴标签，给不出承诺的准确率 | 陪伴探索，不给答案，不施压 |
| 结局 | 一次性消费 · 难留存 · 难付费 | 高留存 · 落在付费点（行动层） |

> **图示化记忆**：重构后的完整闭环为——① 探索·采集信号 → ② 发现·去伪存真 → ③ 行动·给建议 → ④ 执行·坚持 → ⑤ 复盘·校准 → 回到 ①（兴趣随人生阶段动态变化）。其中 ①② 属「发现层」（难变现）、③④ 属「行动层」（主付费点）、⑤ + 未来自我属「闭环层」（留存与复购命门）。详见第 6 节。

## 4. 三块核心能力（功能模块）

> 三块能力像「积木」，不同的组装方式 = 不同的产品模式（第 6 节）。它们共同替代了「被动读手机」这条被堵死的路。

### 4.1 模块一：情绪·能量信号（最抗流失的底座）

- **科学依据**：生态瞬时评估（Ecological Momentary Assessment, EMA）+ 自我决定理论（SDT）+ 心流研究。
- **发起人的可行性判断**：发起人明确表示「我自己容易完成」——把方向简化为「想开心的事 = 心流；难受/抗拒的事 = 内耗」，两个方向即可。
- **研讨升级口径（比「开心/难过」更准）**：
  1. **别记「开心 / 难过」，要记「滋养 / 耗竭」**。一个活动可能让你开心但耗竭（如刷短视频很爽但事后空虚），也可能有抗拒但完成后有充实感（如健身）。**真正指向兴趣的信号，是后者：有抗拒、但做完有「能量回充感」。**（这正是发起人原文档「奶头乐 ≠ 真兴趣」的科学版。）
  2. **信的不是某一天，而是 2–4 周的「一致性」**。单天判断会骗人；连续记录后，「哪类活动反复给你回充能量」才会稳定浮现。
- **产品化的最小形态**：
  - 每天 **1 分钟**，回答 2 个问题：今天哪件事让你「忘了时间（心流）」，哪件事让你「耗尽 / 抗拒」。
  - 统一打分：**心流度（1–5 分）+ 能量感（回充 / 耗竭）**。
  - 2–4 周后输出「你的能量-心流模式图」，指出哪些活动持续滋养你。
- **核心价值**：成本极低、易坚持，是整套产品的「抗流失底座」；但它单独输出偏「认识自我」，需要再接行动（否则用户会问「然后呢」）。

### 4.2 模块二：兴趣小实验（把「发现」变成「验证」）

- **科学依据**：生涯采样（career exploration sampling）、体验式学习（Kolb 经验学习循环）、试错学习。
- **发起人的关键澄清问题**：「A 方向」到底是精准方向 + 对应小任务，还是大方向包含很多小方向的小任务？
  - **答：双层嵌套，且建议「跨类采样」。**
    - **A 方向 = 大方向（顶层分类，约 8 类）**，每个大方向下挂多个**具体微任务（小实验）**。
    - 因为用户还不确定偏向哪类，**先别在一类里扎太深，而是每周从不同大类各抽 1 个微任务**，广撒网覆盖，几周后看数据收敛。
- **关键设计**：每个微实验结束，**统一记同样 2 个问题**（心流度 1–5 + 能量感：回充 / 耗竭），这样数据跨方向可比，App 才能说「你在 X 类的投入度和能量感显著更高」。
- **8 大方向 + 具体微任务种子库**（每个约 2–3 小时，本周可完成）：

| 大方向 | 具体微任务示例 |
| --- | --- |
| 文字·表达 | 写 2000 字随笔，不设主题看能写到哪停不下来；给一位熟人写一封「不寄出的信」 |
| 科技·动手 | 用 AI + 代码做一个能用的自动小工具（如整理文件脚本）；拆一件闲置旧物研究原理再装回 |
| 创造·设计 | 拍 9 张统一主题的照片并排版；做一件「无用但你觉得美」的手作 |
| 身体·自然 | 连 3 天每天 20 分钟做一项从没试过的运动；一次不带耳机的 30 分钟徒步/骑行 |
| 助人·人际 | 免费为一个人做一件具体有用的事；采访一个人「他一生中最满足的一件事」 |
| 经营·组织 | 为一个周末市集摊位写一份完整执行清单；组织一次 3 人以上的小活动 |
| 探究·知识 | 把一个随口问出的小问题研究透写成半页小结；用一张图讲清你最近学到的概念 |
| 表演·镜头 | 录一段 3 分钟「给未来自己」的话；用手机剪一支 30 秒生活 Vlog |

> 注：以上为第一批「种子」，方向与任务后续可继续生长 / 扩充，属于可维护内容库，不是封闭清单。

- **优点**：输出是「行动 + 方向」，直接指向下一步；最契合发起人「找到值得投入的方向」的原始目标；把「发现」变成「验证」。
- **缺点 / 风险**：需要用户每周真花 2–3 小时（**执行门槛 = 留存风险**）；实验设计本身要花功夫打磨。

### 4.3 模块三：过去自我挖掘（高危区，必须安全化）

- **发起人的背景与观察**：发起人 2026 年 1 月在西安图书馆读过《自卑与超越》及阿德勒心理学相关内容，接触过「通过引导回忆、甚至催眠去找深层记忆 / 童年记忆」的方法；但认为**没有专业引导师，自己很难进入那个状态**。因此提问：**能否在软件中做一个「心理引导师」角色**来完成这件事？有没有更好的方法？
- **研讨结论（诚实建议）：不要做催眠 / 深层记忆回溯。** 理由三条：
  1. **临床领域**：没有训练的人自己进不去；这是心理治疗范畴。
  2. **安全风险**：对低谷期用户，可能「翻出不安全的情感」。
  3. **合规风险**：作为非临床 App，深度心理干预有「无证从事心理治疗」的合规隐患。
- **替代方案（更安全、同样有力）：**
  1. **结构化回忆引导（不是催眠）**：用温和提示词，安全地带用户回到过去。示例问题：
     - 「你 12 岁时，什么事会让你忘记吃饭？」
     - 「学生时代有没有一件没人要求、你却反复做的事？」
     - 「有件小时候想做、到现在还没放下的事是什么？」
     - 原则：温和、不进入催眠态、不触碰创伤内核。
  2. **「数字足迹」主动导入（对原始想法的最佳升华）**：发起人原设想「读手机数据」其实没死，只是换个**安全**的活法——**让用户主动把自己的购买记录、搜索历史、歌单、收藏夹导入，由 AI 帮 ta 解读其中的兴趣模式**。数据由用户掌控、可随时删除，既拿到真实行为信号，又不碰隐私红线。
  3. **他人视角**：让 3 个懂用户的人回答「你觉得我最容易投入 / 最擅长什么」，作为外部镜像，低风险。
- **安全护栏（必须写进产品，红线）**：AI 引导师一旦捕捉到明显的痛苦 / 情绪崩溃信号，**只做「转介」**——提示寻求专业帮助，**绝不继续教练式深挖**。这是伦理底线，也是法律护身。
- **AI 引导师的定位**：可以做，但要立好调性——**苏格拉底式、平等、陪伴、不评判、不给答案**（这也契合发起人本人在情感陪伴场景中一贯偏好的相处方式）。

## 5. 技术可行性硬墙（必须遵守）

> 本节是**设计红线**。任何后续方案都不得假设可以「被动读取用户手机数据」。

### 5.1 数据读取的系统层限制

- **iOS**：屏幕使用时间 / App 使用时长接口（Screen Time / Family Controls）**只对家长控制类应用开放**，普通 App 拿不到全量 App 使用数据。
- **Android**：UsageStatsManager 等虽有一定能力，但**有限制**，且「回看安装前历史」几乎不可能。
- **结论**：**「被动监控所有 App、甚至回看用户安装前的历史数据」在系统层面基本做不到。** 这不是「用户愿不愿意授权」的问题，而是「平台不给你这个权限」。

### 5.2 即使能拿到，信号也≠兴趣

- 花钱 / 花时间 ≠ 真兴趣：刚需、冲动消费、社交压力、奶头乐会全部混在一起，**准确率无法承诺**。
- 因此原设想的「花钱最多的地方」只能作为**弱信号 / 参考**，不能作为核心机制。

### 5.3 由此确定的产品形态

- 产品形态**重构为**：「**用户主动参与 + 轻量记录 + 引导式自省 + 定向小实验**」，而不是「被动监控手机」。
- 这反而是**差异化机会**：从「玄学测评」走向「可执行的行动陪伴」。
- **伴随的隐私原则**：任何数据（含「数字足迹」导入）都必须由用户**主动选择、可随时删除**；敏感数据处理是对用户的承诺，不是可选项。
- **伴随的心理安全原则**：不做临床级干预，设「转介」护栏（见 4.3）。

## 6. 四种产品模式与市场分析

### 6.1 四种模式对比

> 三块能力（情绪观察 / 兴趣采样 / 叙事自我）像积木，不同组装 = 不同模式。

| 模式 | 科学依据 | 用户每天付出 | 核心输出 | 市场参照与反响 |
| --- | --- | --- | --- | --- |
| **A · 情绪观察（EMA 日记）** | 生态瞬时评估、自我决定理论 | 每天 1 分钟记录 | 2–4 周后「你的能量-心流模式图」，指出哪些活动持续滋养你 | 情绪记录类（Daylio / Moodnotes）**需求大但变现弱**，多小额订阅 |
| **B · 兴趣采样（小实验）** | 生涯采样、体验式学习（Kolb） | 每周花 2–3h 做 1 个小实验 | 几周后收敛出 1–2 个「值得深耕方向」+ 第一周具体动作 | 偏「30 天挑战 / 体验平台」，线上**相对蓝海**，但有执行门槛 |
| **C · 叙事·未来自我（生命故事）** | 叙事认同（McAdams）、可能自我（Markus & Nurius） | 对话式，时长自由 | 「和未来的自己对话」，长期见证自己变成谁 | AI 陪伴 / 树洞赛道**拥挤但订阅变现成熟**，合规要求高 |
| **D · 验证引擎闭环（A→B→C 串联）** | A+B+C 各取所长，形成「观察→验证→养成→见证」 | 分阶段，前期轻后期中 | 找到方向 → 做成事 → 见证成长，全闭环数据沉淀 | 几乎**无同类完整闭环**——真正的差异化蓝海，但需分阶段开发 |

### 6.2 各模式单独做的优缺点

- **单独做 A**：需求真实、留存好做，但「情绪日记」难以单独收高价，**变现天花板低**。
- **单独做 B**：最契合「找到方向」的承诺，但每周要用户真花 2–3 小时，**执行门槛 = 留存风险**，也最考验实验设计。
- **单独做 C**：情感黏性最强、变现最顺，但会滑进拥挤的「AI 陪伴」赛道，也偏离「找兴趣」这个短期刚需。
- **做 D（分阶段闭环）**：差异化最大、护城河最深，但它是「从零到一的完整产品」，**必须靠分阶段控制风险与精力**——正好匹配发起人「先 MVP 验证、再覆盖更年长人群」的节奏。

### 6.3 市场真相（三层看）

| 层级 | 对应环节 | 判断 |
| --- | --- | --- |
| **发现层** | ①② 探索 / 发现 | 需求真，但低频、一次消费、难承诺结果；已被免费性格/职业测评教育成「不该付费」——**难变现** |
| **行动层** | ③④ 行动 / 执行 | 用户付费买的是「把兴趣变成能力的确定性」，高频、可承诺进展——**主战场 / 主付费点** |
| **闭环层** | ⑤ 复盘 + 未来自我对话 | 把一次性发现变成持续关系，解决留存与复购——**命门** |

### 6.4 当前倾向（待发起人最终确认）

- **不做单选题，做分阶段闭环（D）**——但**不要一次全做**。
- 先用一个**薄切片**验证市场（建议 **A + B 薄版**：每天 1 分钟 + 每周 1 个实验，4 周出方向）。
- 跑通后再叠加 C（未来自我对话）。
- 理由：每层都沉淀数据，护城河才最深；A + B 薄版最直接兑现「找到方向」的承诺，也同时验证「用户愿不愿意坚持动起来」。
